What 12 real CLAUDE.md files from major repos look like

We pulled the root CLAUDE.md from 12 well-known repositories at pinned commits on November 14, 2026, measured each one, and hand-reviewed every flag our rules checker raised. Published November 14, 2026.

The short version

Most projects keep this file small. The median is 348 estimated tokens, and 9 of the 12 sit under 2,000. Three files are nothing but pointers to other docs - with an important caveat: a pointer root is only cheap if the file it points to is, because agents that follow the pointer load that file too. We measured root files only, so pointer repos' true instruction weight is understated here. Three files carry real weight: Electron (~3,490), Bun (~4,379) and PyTorch (~4,364), about 1.7% to 2.2% of a 200k context window, every session. And our checker's heuristic warnings mostly did not survive manual review - details below, including a real bug the survey caught in our own tool.

What we found

1. The pattern is "small file, big pointers." The three shortest files (11, 56, 268 chars) defer to AGENTS.md or dedicated guideline docs. React goes further and uses the file for live context: it names the current active work and branch. The file is cheapest when it points instead of repeats - but note the limits of that: the sizes in this table are root files only. A pointer repo's real per-session load includes whatever the agent pulls in by following the pointer, which we did not measure.

2. Three files carry real weight. Electron (~3,490 est. tokens) is safety rules plus a dev guide; Bun (~4,379) is mostly build and test discipline; PyTorch (~4,364) leads with a mandatory AI-contribution policy. At the Claude Sonnet 5.5 list price of $2 per million input tokens (source, checked Nov 13, 2026), even the largest costs under a cent per session load. The real cost is context-window room: 1.7% to 2.2% of a 200k window, every session, before the first prompt.

3. Content clusters into four jobs: orientation (what this repo is), operational discipline (how to build and test here), agent governance (what the agent may do on GitHub), and pointers. PyTorch's governance section is the clearest example of the third: agents must never act autonomously on GitHub, must label AI-generated content, and must open unreviewed PRs as drafts.

4. Heuristic lint flags need a human pass. Our checker raised two "possible contradiction" flags (it pairs the first line containing "always" or "never" with the first line containing a softener like "if needed"). Both were false positives: in Bun, an always-rule about test ports was paired with an unrelated PR-comments line 131 lines away; in PyTorch, an always-rule about draft PRs was paired with an "if needed" that is not an exception to it. Of PyTorch's four hedged-wording flags, two were genuine suggestions ("please try to put it back on a single line", line 238; "you can also consider writing to local files", line 349), one was a negation ("Do NOT try to find alternatives", line 50 - a firm rule, not a hedge), and one was borderline ("consider two user personas", line 314). Treat these flags as review prompts, not verdicts.

5. The survey caught a bug in our own checker. Kotlin's file opens with YAML-style metadata frontmatter (project:, languages:, ...). Our first pass treated any file starting with --- as a Cursor .mdc rule and reported two load-breaking failures that do not exist. We fixed the classifier the same day - it now applies .mdc checks only when the frontmatter actually contains .mdc keys (description, globs, or alwaysApply) - and re-ran the whole sample. Regression behavior on genuinely broken .mdc files is unchanged.

Method

Sample: repositories named in dexio.wiki's guide "CLAUDE.md examples: what 270 top GitHub repos put in them" plus the source list of ArthurClune/claude-md-examples, included if a root CLAUDE.md was fetchable at a pinned commit on Nov 14, 2026. Sizes are root files only; pointer targets (AGENTS.md, .ai/guidelines.md) are not included. microsoft/playwright and p33m5t3r/vibecoding had no root CLAUDE.md and are excluded (documented, not silently dropped). Files were fetched from raw.githubusercontent.com at the commits linked in the table, so every row is reproducible. Analysis ran the exact logic of our rules checker in a script; every non-pass flag was then reviewed by hand against the file, and false positives are reported as such above. Short quoted lines are reproduced for commentary and criticism, with attribution.

Check your own file. Paste your CLAUDE.md, AGENTS.md, or .mdc rule into the AI rules sanity check - it runs in your browser and uploads nothing. If it's long, the cost checker estimates what it weighs per session.
